# Complete Concept C interaction specification

This document defines the interaction state for the current offline app. The catalog and synthetic cloud surfaces have gated designs in this same package. Start from [Antigravity implementation requirements](ANTIGRAVITY_IMPLEMENTATION.md) for ownership, tests and exact mocks. All mock data are synthetic Persian data, fixed to ۲۵ آبان ۱۴۰۵ for screenshots.

## Navigation and route ownership

- **Root:** While resolving local vehicles, show a structure-preserving loading state. Zero vehicles → first-launch surface with Add Vehicle, Restore and Settings. One or more → Home. On Room open/read failure show «دفتر خودرو باز نشد» and Retry. Preserve the database. Empty and failed are separate.
- **Main destinations:** RTL dock order «خانه»، «سوابق»، «یادآورها». Vehicle selection is scoped from Home and retained across the three destinations. Use a single stack per active journey, preserving main-destination scroll by route and vehicle. A tap on the selected tab leaves the current list position. Back at History or Reminders root returns Home; Back at Home follows Android root behavior. Deep child screens and dialogs hide the dock. The top-level entry action is «ثبت جدید» on Home and History, and «ثبت یادآور» on Reminders.
- **Transitions:** Home vehicle selector → scoped select or Manage Vehicles. Recent transaction → record details with Home origin. Due item → reminder detail with Home origin. History → record details or report; record → edit/delete. Reminders → detail or new reminder. Settings → appearance sheet, notification settings, or manual backup; backup → export or restore. First launch also opens restore directly. Internal Back returns to the exact caller and restores its scroll/focus.
- **Sheet rules:** Back/outside/close dismiss without changing a value and restore opener focus. Single-choice selection closes and focuses the updating anchor or destination heading. Confirmation uses «انصراف» and a named action; cancel never executes it. Busy saves ignore duplicate submit and dismissal until current result. Exception for explicitly cancelable existing cloud upload.
- **Edit Back:** Back with the IME visible dismisses it first. Back from an entry then discards that draft following current behavior. Error and recreation keep existing draft survival semantics. Returning from a successful save goes to the original tab/record, with confirmed success announced. Local writes update views via existing observations. After delete, return to the list or Home origin and focus the nearest retained row or section heading.
- **Scope integrity:** Pin vehicle and stable record ID at open. Switching occurs from Home, never inside an in-progress edit. New scope shows pending/empty/failure distinctly. Wait for matching vehicle data before showing due, mileage, history or report. Do not show an old vehicle's values while a new one loads.

## Vehicle onboarding and management

- Empty Home has «افزودن خودرو» plus «بازیابی از فایل پشتیبان». After successful first Add, make that vehicle the active Home scope. From an existing Manage Vehicles list, successful Add returns to the list and leaves previous active vehicle selected. Choosing a different vehicle in the Home sheet changes scope and returns to Home. Cancel leaves the prior vehicle unchanged. Vehicle order uses the existing observed list. A management row opens edit, with no delete or archive affordance.
- Add/edit uses name, optional production year, and calendar choice only when year is entered. New input starts blank, edit is prefilled. When year is cleared, clear the calendar association. Year is exactly four digits, excluding 0000, with Persian, Arabic-Indic and Latin digits normalized. Require supported calendar when a year exists. Missing name → «نام خودرو را وارد کنید.»; invalid year → «سال ساخت را با چهار رقم وارد کنید.»; missing calendar → «تقویم سال ساخت را انتخاب کنید.»; missing existing vehicle → «این خودرو دیگر در دسترس نیست.»; write failure → «خودرو ذخیره نشد. دوباره تلاش کنید.» Retain draft and focus faulty field, or preserve list on failure. During mutation show «در حال ذخیره…».
- Optional catalog appears only when the existing catalog state supplies approved entries. Choosing a model sets the supported key and label according to existing logic and returns to the same draft. Keep search, no-match text «مدلی پیدا نشد» and manual entry. No remote content or enrichment. Unsupported/failed catalog load preserves manual path; the synthetic catalog mock is gated, with no new assets required.

## Home, entry and records

- New expense uses a top-left × with a 48 dp touch target and the accessible label «بستن فرم ثبت هزینه». Tapping it dismisses the unsaved draft using the existing cancel route. Disable the action while saving. The footer contains the primary save action.

- Home order is current vehicle/mileage, first due reminder, and newest three records. Other due reminders follow in Reminders and a count appears only when multiple are due. Due text uses actual date or known mileage basis. Hide due line when confirmed clear; unknown mileage reads «هنوز کارکردی ثبت نشده است.» and load failure is indicated separately. Empty recent list uses «هنوز هزینه یا سرویسی ثبت نشده است.» Recent read failure offers «تلاش دوباره» without blocking entry. Use real date/category/amount/volume; no fabricated totals.
- «ثبت جدید» opens the three-row entry sheet. «سوخت» maps to existing fuel key. «هزینه» permits insurance, wash and other. «سرویس» permits oil change, repair and parts. Expense and Service share the non-fuel form and leave category blank until chosen. Fresh fuel shows total payment and volume; use the Tehran civil date captured when draft opens. Date can be changed on its disclosure row. Keep notes and mileage collapsed for fresh drafts, initially expand when an existing value or field error warrants. Core Save action is «ثبت سوخت»، «ثبت هزینه»، or «ثبت سرویس». Edit uses «ذخیره تغییرات».
- Use exact positive toman, one fractional digit maximum, no out-of-range conversion or float storage. Expense requires an amount. Only oil change, repair, and parts can omit it. Fuel requires positive liters with up to three decimals. No persisted unit price or automatic conversion from a unit-price field. Existing Jalali parser and displayed/stored fallback define all date validation and range. Optional odometer is a nonnegative integer with existing chain validation; omit only explicitly when conflicting or removing a linked reading. Notes remain optional. Update a field, clear its own error and keep other errors.
- Pair digits at default size when the labels fit. The required numeric order is amount then volume, decimal IME; do not auto-open the keyboard on creating a fresh form if doing so would obscure fields at 150%. Next focuses liters, Done hides IME; only the explicit Save commits. Date uses slash-friendly text IME and mileage integer IME. Focus/scroll to first invalid field and open hidden section as needed. Busy copy «در حال ذخیره…». Specific error messages under [Error and result copy](#error-and-result-copy).
- History retains current occurrence-date ordering with existing creation and ID tie-breakers. Group by Jalali month/day where representable, use existing raw date fallback otherwise. No new filter/search. Show category and meaningful detail, end-aligned amount or «بدون مبلغ». Row opens a detail page with category, date, amount, linked mileage/fuel and notes where present. A single edit action opens the existing draft. Unknown/incompatible record stays readable with exact data and usable existing delete capability. Show explicit not-found state if it disappeared, then return to scope with next record anchor.
- Delete actions in details/edit open a confirmation showing category/date, plus linked-reading consequence if present. Confirm «حذف ثبت» uses the existing scoped delete. Cancel restores the action. Failure keeps details/draft and displays outcome. On an edit, category may change among all seven keys using existing policies. Non-fuel hides fuel volume; selecting Fuel requires liters. Keep the original Gregorian date when applicable and preserve original linked-mileage semantics (keep/set/remove). Explicit removal is reversible until Save. A mileage conflict offers «ثبت بدون کارکرد» with the existing removal implication. Standalone odometer storage and backup behavior remains intact. No standalone app form is introduced.

## Monthly reporting

- Enter from the report row at the top of History. Show active vehicle, selected month and picker. Start with current Tehran Jalali month when supported. Choices are the existing available months ordered newest first, drawn from the current month and actual reported months. If current date is unsupported, show the underlying unsupported-date hint and available valid options rather than inventing a month. Back from picker keeps month; Back from report goes to same History.
- For populated months show exact BigInteger total in toman, entry count and count of records with no amount. Detail categories use existing keys and totals, shown largest priced amount first and stable category order for ties; render zero/unknown/unpriced according to source data, with «بدون مبلغ» only if no priced entries in that category. Bars express share from numeric totals and are hidden from TalkBack. Retain unassigned entries as an explicit fallback block with original date/reason. Empty month is «در این ماه ثبتی ندارید» and a still-accessible picker. All-unpriced month keeps record count and zero known sum with an explicit unpriced label.
- Initial load uses placeholder, report failure gives «گزارش بارگیری نشد» and «تلاش دوباره», preserving current month selection. Report never recomputes money from formatted text or bars.

## Reminders and notifications

- Reminders list starts with due, then upcoming, then past. Use existing sort within groups. Active row opens detail, where title, threshold, status and relevant dates/mileage are visible. Upcoming mileage shows remaining difference only with valid known reading and positive difference. Without reading show «برای بررسی این یادآور، کارکرد خودرو لازم است.» Closed reminders are read-only with explicit «انجام‌شده» or «لغوشده».
- «ثبت یادآور» opens title plus threshold. Default type is date, both values begin blank. Changing type switches visible field and retains typed text in the current draft; only selected threshold is written. Date is correct Jalali, mileage is a nonnegative whole kilometer. Same confirmed in-app lifecycle and scheduling. On success return to Reminders. Pending saves show «در حال ثبت…». Failed load or mutate stays in scope, showing Retry or retained input. Stale/nonactive action shows «این یادآور دیگر فعال نیست.» with Back.
- Complete via «انجام شد» in details. Cancel via «لغو یادآور» and a confirmation (states it remains as canceled in history). After success return to origin with confirmation; after failure retain detail. No reschedule, recurring calculation, edit or delete feature is added for existing reminders.
- Settings → Notifications presents off, on, and blocked from the existing opt-in and platform state. Opt-in uses the current runtime permission flow and schedule reconciliation. Device/channel-blocked shows settings action; after return refresh state. Opt-out stays local. Do not ask permissions for basic logging. Explain possible delays and in-app due state, preserve date-only notification behavior and notification launch routing.

## Settings and manual recovery

- Settings opens from Home/first launch. Theme chooser lists system/light/dark with current selection marked, applies immediately and persists through existing prefs. Closing picker restores focus. Theme switch changes system chrome and preserves route; editable content follows existing saveability. No new setting storage contract.
- Settings → «پشتیبان‌گیری دستی» offers export and restore. Export prep says file contains all current vehicles and records and is readable plaintext. «انتخاب محل ذخیره» opens existing CreateDocument with JSON MIME and existing filename convention. Picker cancel keeps prep. After choosing a location, block duplicate requests and show «در حال ذخیره فایل پشتیبان…». Success only after write and stream completion. Show result with «بازگشت» to Backup. Export is an explicit point-in-time copy, so later changes require another export.
- Restore prep names empty-ledger requirement and «انتخاب فایل پشتیبان» opens existing OpenDocument. On cancel remain in prep. Once selected, use existing repository validation and single transaction. Keep progress busy until complete, with «در حال بررسی فایل و بازیابی…». Populated ledger shows why it was rejected, leaves data as-is, and offers Back. Invalid/unsupported/unavailable/oversize show the appropriate outcome and a path to another file. Success and success-with-notification-warning are different and only shown after commit. On the success screen «رفتن به دفتر خودرو» goes to resolved Home/first launch depending on resulting vehicles. Back returns to caller. No erase, merge or overwrite action.
- Settings absent cloud row when flag is off. The gated synthetic cloud entry is fully specified in [GATED_CLOUD.md](GATED_CLOUD.md), with current flags and operations intact.

## Error and result copy

Use native passive outcome/status region and existing domain result enums. Below is the intended Persian copy and recovery. Keep progress distinct from success and announce each once. Technical exception strings never appear in the UX.

| Operation or result | Copy and action |
|---|---|
| Blank amount / invalid amount | «مبلغ را وارد کنید.» / «مبلغ مثبت را با حداکثر یک رقم اعشار وارد کنید.» Focus amount. |
| Invalid category / volume | «دسته‌بندی را انتخاب کنید.» / «حجم مثبت را با حداکثر سه رقم اعشار وارد کنید.» Focus category or liters. |
| Invalid date / mileage | «تاریخ شمسی معتبری وارد کنید.» / «کارکرد را به کیلومتر و بدون اعشار وارد کنید.» Expand and focus. |
| Mileage conflict | «کارکرد با ثبت‌های قبل یا بعد از این تاریخ سازگار نیست.» Keep correction or «ثبت بدون کارکرد». If an edit removes an existing reading, show «کارکرد همراه این ثبت حذف می‌شود.» before that action. |
| Storage or domain write rejected | «تغییرات ذخیره نشد. دوباره تلاش کنید.» Keep state and retry. For nonretryable incompatible or missing rows, show reason and Back. |
| Save / delete success | «ثبت ذخیره شد.» / «ثبت حذف شد.» Return to the calling context. |
| Reminder validation / write / lifecycle | «عنوان یادآور را وارد کنید.» / «موعد معتبری وارد کنید.» / «یادآور ذخیره نشد.» / «یادآور انجام شد.» / «یادآور لغو شد.» Use inline errors for input, status for confirmed outcome. |
| Backup Canceled | Remain on prep. Optional text «انتخاب فایل لغو شد.» No error tone. |
| Backup LedgerPopulated | «دفتر خودرو خالی نیست. اطلاعات فعلی حفظ شد.» Back. |
| Backup TooLarge | «اندازهٔ فایل یا تعداد ثبت‌ها از حد مجاز بیشتر است.» Restore offers Choose another file; export returns to prep/details. |
| Backup UnsupportedFormat / InvalidData | «قالب فایل پشتیبانی نمی‌شود.» / «فایل پشتیبان معتبر نیست.» Choose another file. On export invalid data, show storage failure state with Back, not a picker for input. |
| Backup FileUnavailable | Export «فایل ذخیره نشد. محل دیگری انتخاب کنید.» / Restore «فایل باز نشد. فایل دیگری انتخاب کنید.» |
| Backup StorageFailure | «دسترسی به اطلاعات دفتر خودرو ممکن نشد.» Retry or Back depending on safe operation outcome. |
| Backup Exported / Restored | «فایل پشتیبان ذخیره شد.» / «اطلاعات بازیابی شد.» Return or go to ledger. |
| Backup RestoredWithNotificationWarning | «اطلاعات بازیابی شد. بررسی اعلان‌ها کامل نشد.» Offer ledger and notification settings via regular route. Never offer repeat import in this result. |
