# Concept C · gated synthetic cloud interface

This section applies to the already existing debug-only synthetic feature. Keep `LOCAL_CLOUD_ENABLED`, the existing localhost-only development setup, manifest differences, and the nullable CloudSettingsViewModel boundary exactly as they exist. Settings exposes «پشتیبان آنلاین» only when that view model is present. Screens depict fictional data; the offline release exposes only manual recovery. Do not interpret this design as authorization for accounts, production hosting, endpoints or changes to authentication.

## Screen layout and state mapping

Reuse the app bar, outlined fields, status notice, action footer and modal tokens from [design system](DESIGN_SYSTEM.md). Keep sensitive window and dialogs secure. App labels are Persian. Usernames, revisions and recovery codes are isolated LTR. Password fields are obscured. No sensitive data may appear in logs or saved UI state.

| Existing state | Render and action |
|---|---|
| Loading, signed out | App bar «پشتیبان آنلاین» plus synthetic-only warning. Loading placeholder and one announcement. In signed-out state show «ورود», username and password, with outlined register and recovery actions. Existing submit uses current constraints and stable control tags. [Sign-in PNG](previews/c-cloud-auth.png) |
| Register / recover | Replace form mode in place. Register adds existing invitation field. Recover labels password «گذرواژه جدید» and the code «کد بازیابی». Keep username on mode switch and clear password and code in memory. Apply existing field limits and platform keyboards. Primary action matches mode. Return to sign-in using existing alternative; Back returns Settings after dismissing the IME. |
| One-time recovery code | A secure protected modal displays code once with existing instructions. The only closing action is «کد را یادداشت کردم». Outside taps and Back do not dismiss it. Never copy codes automatically. [Protected-code layout](previews/c-cloud-recovery.png) |
| Signed in, unbound / other account | Show identity and binding status; offer existing association action in binder confirmation. If bound elsewhere, show explicit other-account wording and preserve the empty/authorization restrictions before accepting. Sign out available. No upload or restore action before bound state. |
| Bound, no acknowledgment / acknowledged | State empty-after-load as «پشتیبان تأییدشده‌ای ندارید» or show exact last acknowledged date and isolated revision. Upload and review restore choices follow bound state. Sign out remains quiet. [Bound PNG](previews/c-cloud-bound.png) |
| Pending / reconciliation | When existing state says Pending, show status «ارسال هنوز تأیید نشده است» and existing Retry plus secondary Review. When state says Review, primary action is Review. Review modal shows whether existing remote snapshot will be replaced, with acknowledgment time if available and explicit Send New. Preserve revision/ack/intent semantics. |
| Busy | Display existing progress and operation-specific label (load, send, or restore). Disable duplicate requests and Back as current ViewModel does while busy. Only sending offers existing Cancel Upload. Do not infer success from dismissal, preliminary response or elapsed time. |
| Restore preview | Show exact acknowledged time, expiry and isolated revision of selected snapshot. Explain empty-ledger requirement. Explicit «بازیابی این نسخه» is the only commit action. Keep secure policy and recheck ownership, version and empty ledger at confirmation. Dismiss preview without import. [Restore review PNG](previews/c-cloud-restore.png) |
| Upload / restore result | Map typed states to a status adjacent to the operation. Success belongs to acknowledged result only. A restore warning follows commit and must not be offered as retry. Keep manual routes reachable through Settings. |

## Outcome rules

Keep the Persian wording already mapped by `CloudSettingsScreen.issueLabel` and `res/values/cloud_strings.xml` for input, credentials, registration conflict, session expiry, binding required, other account, populated ledger, rate limit, offline, unconfirmed, conflict, rejected/storage, missing snapshot, changed restore, interrupted/oversize download, invalid restore, restored with or without warning, and upload success. Make only the next currently supported action available. Invalid credentials or input preserves the appropriate form and clears ephemeral secrets under existing rules. Expired account returns existing sign-in behavior. Changed snapshot or conflict takes the user through current review instead of blindly retrying. Preserve sender/receiver ownership, optimistic versioning, explicit replacement, and the existing recovery constraints. No live sync, merge or deletion workflow is introduced.
