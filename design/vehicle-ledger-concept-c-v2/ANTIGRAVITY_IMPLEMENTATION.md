## Recommended order

1. **Theme and components.** Add semantic tokens to existing Material theme and reusable shell, dock, row, status, disclosure, field and form footer. Compose theme/RTL/IME and contrast checks first. Keep existing font and dependencies.
2. **Root, vehicle and scope.** Introduce a single presentation navigator with Home, History, Reminders and origin-aware children. Wire first launch, vehicle choice and manage/add/edit flows. Reset stale-scoped reads and retain existing repositories/keys. Test Back and delayed observations.
3. **Capture and transactions.** Separate entry intent by category grouping. Reuse existing draft, parsing and state/result ownership. Add detail, edit, delete confirmation, retained History scroll and per-vehicle source. Exercise money, dates, linked mileage, and save/dismiss guards.
4. **Reporting and reminders.** Build monthly totals/month picker on the existing state. Place reminders list first and retain current actions and scheduling. Test current date boundaries and due rules.
5. **Settings and recovery.** Apply appearance, notifications, manual backup and restore results. Retain platform activity-result contracts. Adapt only the gated cloud presentation and bind its existing state machine. Test both flag states and document picker behavior.
6. **Parity and regression.** Compare both appearances, field and keyboard behavior, recovery status, physical accessibility and offline regressions. Record results in the project execution record after implementation is authorized. Use existing test tooling and presets.

## Non-negotiable invariants

- Existing architecture and one app module, Kotlin/Compose with screen-level StateFlow and manual dependencies. Repositories own transactions and persistence. UI state and callbacks must never introduce extra writes.
- Room schema v4, existing migration and data fallback policies, stable IDs and references. Preserve original database on open failure. Preserve current History ordering semantics and stored date and text raw values.
- Legacy integer rials, exact decimal parsing, checked Long limits and BigInteger aggregate arithmetic. Same supported decimal rules, category keys and unpriced outcomes. Preserve Tehran defaults and current supported Jalali conversions and forecasts. No new price-per-liter contract.
- Linked mileage chronology, keep/set/remove and delete cascade. Preserve existing standalone reading storage semantics and the explicit conflict save path. Keep retry writes safe and no duplicate mutations.
- Reminder state transitions, Tehran date rules, scheduling, opt-in, API-specific notifications and device channel blocking. Date-only notifications remain best effort. Due and mileage reminders remain visible in app.
- Snapshot format v1, exact payload and existing 4 MiB inclusive and collection bounds. Export via explicit CreateDocument with JSON. Restore validates all rows, rechecks completely empty ledger inside commit, and inserts atomically. No erase, merge, silent overwrite or automatic export.
- Preserve current dark/system preference behavior, backup exclusions, file/permissions boundaries, local offline functionality, gated catalog, and synthetic cloud flags/security. No production cloud activation, dependency additions, signing or release artifact changes as part of presentation implementation.
