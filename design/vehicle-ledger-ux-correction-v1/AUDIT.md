### Persian, accessibility and visual identity

- `03_home_single_vehicle.png`, `05_quick_add_form.png` and `07_history_screen.png` show Persian digits and broadly correct RTL placement. The observed typographic problem is density inside constrained containers, especially the volume label in `12_font150_quick_add.png` and action wrapping in `13_font150_home.png`. The mixed-script vehicle label appears as a recognizable unit in these examples. No general bidi failure is established. Use a single Persian family, explicit unit labels, direction-isolated values and flexible line heights. **Major** for the enlarged entry layout.
- `03_home_single_vehicle.png`, `07_history_screen.png` and `10_reminders_screen.png` share a consistent color vocabulary. Their repeated rounded shells, tinted icon blocks and buttons create a generic modular look. Distinctiveness should come from task-priority placement or a date-and-value layout. Preserve status color where it encodes urgency. **Major** for overall composition.
- `06_quick_add_validation_error.png` and the dark captures identify useful test targets. Static images cannot establish measured touch bounds, focus traversal, full user task time, TalkBack behavior, actual contrast ratios, or whether money and dates round-trip correctly. No Critical defect is confirmed by the static frames.

### Source-confirmed behavior

- Both Home launch callbacks currently resolve to `ledger::openQuickAdd`. Drafts default to Fuel and the category picker is shown only when the draft is non-fuel or editing. The separate-looking Home actions therefore lack distinct fresh draft behavior in this checkout. This is a source finding, as the PNG set contains no general-expense capture.
- `EntryFormScreen` wraps header, fields and Save in the same vertically scrolling column with IME padding. Optional details initialize expanded. History already groups by date and has per-vehicle scroll state. The declared “sticky” button comment does not change the layout hierarchy.
- `HomeViewModel` clears the old mileage on switch and starts a new observation, but previous recent rows can remain until the new history flow emits. The switching mockups illustrate correct scope, not observed stale data in the PNGs.
- `RemindersScreen` inserts the reminder creation form ahead of the observed list. No business rule requires that order.
- Room v4, snapshot v1, exact integer legacy-rial money, whole-milliliter fuel, optional linked odometer, existing reminder thresholds/lifecycle, Tehran/Jalali dates and offline recovery remain fixed. Both redesigns fit presentation/UI state changes. A persisted default vehicle, unit-price entry/derivation, resume-after-process-death drafts, and changes to reminder or backup rules would need a separate decision. No new domain assumptions are needed for either concept.
