# Antigravity implementation handoff

**Proposed · design review only.** Use signed RC5 behavior and documented data contracts as the functional reference. Use the owner-approved subset of this package as the presentation reference. Resolve the source baseline with the owner before editing. The current checkout has no Git baseline for isolating the rejected design.

## Behavior to preserve

1. Keep the single Android app module, Kotlin/Compose Material 3, screen-level ViewModels with StateFlow, concrete repositories and manual dependency wiring. Use string resources for Persian. Keep transactions and validation in their existing layers.
2. Pin Room v4 and migrations, preserve record IDs and persisted fields and relationships. Preserve History query ordering, including same-date tie breaks. History contains expense/service entries with optional linked readings. Standalone readings remain available to the latest-mileage query and backup.
3. Use existing exact legacy-rial Money and monthly BigInteger arithmetic. Sum priced rows and count unpriced rows. Fuel volumes use whole milliliters and mileage uses whole kilometers. The sample total is 6,570,000 toman across six current-month records, one unpriced. Bars are derived from aggregate shares and never feed the totals.
4. Keep JalaliDates, Tehran civil month and draft date, supported 1300–1498 range and original date fallback. Report choices are the current month plus months already represented in the source state. Keep stored Gregorian dates and note text, including date exceptions.
5. Preserve entry save/update/delete rules. Fuel, wash, insurance and other need a positive amount. Fuel also needs positive liters. Linked mileage belongs to the same vehicle and date, has chronological bounds and explicit Keep/Set/Remove. Deleting an entry removes its linked reading. A retry of one pending input preserves its draft UUID and creation time. Reuse write guards and atomic operations.
6. Reminders are manual, date or mileage, with active/completed/canceled persisted states and derived due status. Keep correct threshold calculations, system scheduling and post-action cleanup. Notifications are date-only, opt-in and best effort. Logging and in-app due reminders work offline.
7. Keep snapshot v1, SAF and typed outcomes. Preserve 4 MiB inclusive and collection limits. Export is explicit, plaintext and whole-ledger as of capture. Restore requires every target table empty and must retain pre-read and transactional checks, validation and rollback. A notification-reset warning follows data commit. Do not retry import in response to that warning.
8. Keep cloud disabled for the offline distribution path, with existing synthetic implementation gated. Preserve account ownership/authentication boundaries, signed artifacts, package identity and signing lineage.

## Presentation contracts

Use one route owner for Home, Notebook(vehicle ID, view), Entry(vehicle ID, mode, origin), Reminders(vehicle ID), Reminder Form(vehicle ID), Vehicle Form(target ID, origin), Settings(origin), and File Recovery(action, origin). The names describe UI boundaries. Extend existing state or use one scoped presentation coordinator. No dependency follows from these interfaces.

- Vehicle destinations take stable IDs. An Edit route needs the specific entry or target ID. Scope is immutable while editing. Preserve app-supported recreation behavior. Retain list position separately by vehicle/view. Return from edit to the same History anchor. If deleted, focus the next row or heading.
- Use distinct loading, content, empty, and failure states. If Home's mileage observer collapses read failure into absence today, map that failure distinctly before showing missing-mileage copy. A new vehicle scope cancels or invalidates previous display results. Preserve exact report outputs and visible source fallbacks.
- Translate typed results into locally actionable field errors or durable operation outcomes. Keep the draft on failure. Make explicit submit/delete intent single-flight using the existing state guards. Successful feedback follows the repository result. A failed delete keeps the originating form/list state.
- Keep existing picker/URI boundary. Null selection is cancellation. Invalid URI or provider is recoverable, and the restore commit check is authoritative. Keep original invocation context on callback after recreation, and avoid duplicate pickers and writes.
- Notification settings consume local opt-in and OS permission independently, refresh on resume, and link to OS settings when blocked. No new domain input, result enum, database schema, API or external service is specified.

## Future cloud UX boundary

A later authorized recovery option can sit beside Manual Backup in app-wide Settings, with an eligible first-launch route. It needs separate decisions about custody and real data, consent, account state, last acknowledged snapshot age, explicit upload/download, stale and interrupted transfers, and separate account deletion. Name the snapshot and its acknowledged date. Unavailability leaves local logging available and offers manual recovery. Restore obeys the empty-target contract.
