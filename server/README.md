# Vehicle Ledger local recovery API

Use Node.js 26.13 or a later Node.js 26 LTS patch. The service uses TypeScript with Node's native type stripping, Fastify 5.12.8, node-postgres 8.23.0 and Node's built-in Argon2id. See the [API contract](../docs/architecture/API_DESIGN.md#accounts-and-sessions). This workflow is for synthetic local accounts.

## Prepare and test

1. Extract the official Debian amd64 PostgreSQL 18 server, client and libpq packages into an ignored build directory. Use a patched release, at least 18.7. The test command expects the Debian layout, including `usr/lib/postgresql/18/bin` and `usr/share/postgresql/18`. Verify packages against the signed repository index before extracting.
2. Put the existing Node 26 distribution and its npm on `PATH` and set `VEHICLE_PG_TOOLS` to the absolute extraction root.
3. Run from the project root.

```bash
npm --prefix server ci --ignore-scripts --omit=optional
export VEHICLE_PG_TOOLS=/absolute/path/to/extracted/postgresql
bash server/test/local-postgres.sh test
```

The script initializes a fresh cluster as the current non-root user in a unique `/tmp/vehicle-m51.*` directory. PostgreSQL uses a private mode-0700 Unix socket and has TCP listening disabled. Peer authentication maps the local OS owner to separate database roles. The migrator owns the test database, the runtime role cannot run DDL or issue invites, and the invite role cannot read credentials. The database has no public access. The local OS owner controls the whole fixture, including administration. Use an isolated existing OS account if that trust boundary is insufficient. The script stops the cluster on exit and prints the retained path.

## Run locally

```bash
bash server/test/local-postgres.sh dev
```

This starts a separate development database, applies migrations, generates a process-local throttle key, sets a one-hour synthetic snapshot lifetime, and serves Fastify on `127.0.0.1:8765`. The script prints a separate-terminal command to issue one synthetic invite. Run that command from the `server` directory. The invite is displayed once to the operator. Keep it out of terminal captures, shell history and shared logs. For revocation run `node src/admin.ts revoke-invite` with the same socket and database environment and pass the invite's hex SHA-256 verifier on stdin. Only the operator role can issue or revoke an unredeemed invite. Registration, login and recovery return bearer material directly to the caller. Use `POST /v1/auth/logout` with a bearer and an empty body.

For a manually managed disposable instance, set `VEHICLE_PG_SOCKET` to its owned private socket directory, `VEHICLE_PG_DATABASE` to a database named `vehicle_m51_…`, `VEHICLE_THROTTLE_KEY` to 32 random bytes in lowercase hex, and `VEHICLE_LOCAL_SNAPSHOT_TTL_SECONDS` to an explicit synthetic-only lifetime from 1 to 604800 seconds. Keep the key stable across processes using the same cluster so throttle buckets survive API restarts. Keep the key outside source and terminal history. Run `npm run migrate` and `npm start` from `server`. A different loopback port can be set with `VEHICLE_HTTP_PORT`.

To tear down a script-owned fixture, exit the command or use Ctrl+C for the development listener. If stopped abnormally, verify that the printed path belongs to your disposable fixture and stop that exact cluster with `pg_ctl -D "$fixture/data" -m fast -w stop` from the extracted PostgreSQL toolchain. Delete only the verified disposable fixture directory after confirming it has stopped and you no longer need the synthetic results.

## Snapshot contract

The M5.2 API exposes authenticated `GET /v1/backup/metadata`, `PUT /v1/backup` and `GET /v1/backup`. Start with metadata and use its quoted `ETag` as `If-Match`. For PUT supply a fresh lowercase UUID in `Idempotency-Key`, `Snapshot-Format: snapshot-v1` and the original UTF-8 JSON bytes. Retry the exact same request if acknowledgement is lost. Downloads use the selected revision in `If-Match` and return the original bytes. See the [API details](../docs/architecture/API_DESIGN.md#snapshot-requests).

The committed [signed M4 export fixture](test/fixtures/m4-signed-export.json) was generated by the unmodified signed M4 APK through SAF with synthetic data on the isolated M4.6 API 37 emulator. It is copied byte-for-byte from the retained export. [M4.6 provenance](../docs/delivery/ANDROID_RELEASE.md#m46-independent-signer-and-emulator-checks)

## Before external deployment

M5.2 is for local synthetic fixtures. External deployment requires separate authorization, HTTPS, encrypted database and backups, least-privilege OS and database identities for each service, secret custody and rotation, redacted ingress logging, and validated resource limits on the intended host. Benchmark the Argon2id profile and review rate limits for real network conditions. A compromised bearer remains usable until revoked or expired. A driver who loses both the password and the valid recovery code has no operator reset path under the current contract. Snapshot operations recheck session authorization under the account-row lock. The local ingress budget is process-local. Snapshot expiry transitions and receipt cleanup are triggered by authorized requests. Production retention, scheduled purge and operational backup lifecycle require separate approval.
